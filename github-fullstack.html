0 · Why a second backend + a frontend

Project 1 left you with a real platform: Postgres and Elasticsearch full of live GitHub events, and a Django/DRF API. It had no face, and it did everything with one framework. This project fixes both — and in doing so teaches a pattern you'll meet in every real system: polyglot services.

┌──────────────┐ /api/search ┌──────────────────┐ query ┌───────────────┐ │ Nuxt (Vue) │ ───────────────▶ │ FastAPI │ ─────────▶ │ Elasticsearch │ │ browser UI │ (server proxy) │ search-api │ (async) │ (from P1) │ └──────────────┘ ◀─────────────── └──────────────────┘ ◀───────── └───────▲───────┘ JSON │ indexed │ by P1's ┌──────────────┐ writes/admin ┌──────────────────┐ write ┌────────┴──────┐ │ (P1) Django │ ───────────────▶ │ ingest + ORM │ ─────────▶ │ PostgreSQL │ └──────────────┘ └──────────────────┘ └───────────────┘ Django owns WRITES + ingest. FastAPI owns READS/search. Nuxt is the UI.
Why not just add this to Django? You could. But splitting responsibilities is the lesson: Django shines at the ORM, migrations, admin, and write-side business logic; FastAPI is a lean, async, auto-documented layer that's perfect for a read-heavy search API talking to Elasticsearch. Running both against the same data is a genuine, common architecture — and it means by Project 3 you'll have two services to put on Kafka and three to deploy to Kubernetes. More services, more reps.
  • FastAPI — async endpoints, Pydantic models, automatic OpenAPI docs, querying ES.
  • Nuxt 3 (Vue) — pages, composables (useFetch), a Nitro server proxy, SSR.
  • Elasticsearch — the same github-events index P1 built. We only read it.
  • Docker Compose — the P1 stack grows two more services and comes up with one command.
This project depends on Project 1 The FastAPI service reads the github-events Elasticsearch index that Project 1 creates and fills. Do P1 first (at least far enough to have ingested + reindexed some events), or nothing here will return results. Step 1 gives you the exact commands to get P1's data flowing again.

Gotcha — you need elasticsearch[async], not elasticsearch The async client (AsyncElasticsearch) requires an async HTTP backend (aiohttp) that the bare package does not pull in. Because we construct the client at import time, a plain elasticsearch dependency blows up the moment the app loads — before any request — with ValueError: You must have 'aiohttp' installed…. The [async] extra fixes it. This bites even in tests that never touch a real ES, because the client object is still created.

3 · Settings & the ES client

Teach. Same 12-factor idea as P1: the Elasticsearch URL and index name come from the environment so the identical code runs on your laptop (localhost:9200) and in Compose (search:9200). Then one shared async client for the whole process.

search-api/app/settings.py 
import os


class Settings:
    """Minimal env-driven settings."""

    ES_URL: str = os.environ.get("ES_URL", "http://localhost:9200")
    ES_INDEX: str = os.environ.get("ES_INDEX", "github-events")


settings = Settings()
search-api/app/es.py 
from elasticsearch import AsyncElasticsearch

from app.settings import settings

# Single shared async client for the app's lifetime.
es = AsyncElasticsearch(hosts=[settings.ES_URL])
Why one shared client AsyncElasticsearch holds a connection pool. You create it once at import and reuse it across every request — building a new client per request would leak connections and kill throughput. The same rule applied to the Kafka producer in P1.

4 · Pydantic response models

Teach. FastAPI uses Pydantic models to define and validate the shape of responses. Declare what a search hit looks like once, and FastAPI both enforces it and publishes it in the auto-generated OpenAPI docs. This is the FastAPI analogue of a DRF serializer.

search-api/app/schemas.py 
from pydantic import BaseModel


class EventHit(BaseModel):
    type: str
    actor_login: str
    repo_name: str
    message: str
    created_at: str
    score: float


class SearchResponse(BaseModel):
    total: int
    results: list[EventHit]


class RepoStat(BaseModel):
    repo: str
    events: int
Why declare response models Set as a route's response_model (next steps), these classes make FastAPI validate and filter the output, generate typed JSON schema for /docs, and give your editor autocomplete. The frontend's TypeScript types in step 12 mirror these exactly — one contract, both ends.

5 · The /search endpoint

Teach. This is the same Elasticsearch query you wrote in P1 — multi_match for the text, a bool query to add filters — but now served by an async FastAPI handler. We build it in two passes: first a bare full-text search, then filters and pagination.

Pass 1 — full-text only

Notice _to_hit maps one ES hit (its _source plus the relevance _score) into your Pydantic model. The handler is async def and awaits the client.

search-api/app/routers/search.py — first pass 
from fastapi import APIRouter
from app.es import es
from app.schemas import EventHit, SearchResponse
from app.settings import settings

router = APIRouter()


def _to_hit(hit: dict) -> EventHit:
    src = hit.get("_source", {})
    return EventHit(
        type=src.get("type", ""),
        actor_login=src.get("actor_login", ""),
        repo_name=src.get("repo_name", ""),
        message=src.get("message", ""),
        created_at=src.get("created_at", ""),
        score=hit.get("_score") or 0.0,
    )


@router.get("/search", response_model=SearchResponse)
async def search(q: str = ""):
    query = {"multi_match": {"query": q, "fields": ["message", "repo_name", "actor_login"]}} \
        if q else {"match_all": {}}
    resp = await es.search(index=settings.ES_INDEX, query=query)
    hits = resp["hits"]
    total = hits["total"]["value"] if isinstance(hits["total"], dict) else hits["total"]
    return SearchResponse(total=total, results=[_to_hit(h) for h in hits["hits"]])
Why async here An ES query is I/O — your handler spends its time waiting on the network. async lets the one process serve other requests during that wait instead of blocking a thread. That's FastAPI's core advantage for a read API like this, and why we use AsyncElasticsearch.

Pass 2 — filters + pagination

Teach. Add type/actor filters (in filter context, not scored) and page/size paging. Note from_ has a trailing underscore because from is a reserved word in Python — the elasticsearch v8 client expects exactly that. Here's the finished router with /search upgraded:

search-api/app/routers/search.py 
from elasticsearch import NotFoundError
from fastapi import APIRouter, HTTPException, Query

from app.es import es
from app.schemas import EventHit, RepoStat, SearchResponse
from app.settings import settings

router = APIRouter()


def _to_hit(hit: dict) -> EventHit:
    src = hit.get("_source", {})
    return EventHit(
        type=src.get("type", ""),
        actor_login=src.get("actor_login", ""),
        repo_name=src.get("repo_name", ""),
        message=src.get("message", ""),
        created_at=src.get("created_at", ""),
        score=hit.get("_score") or 0.0,
    )


@router.get("/search", response_model=SearchResponse)
async def search(
    q: str = "",
    type: str | None = None,
    actor: str | None = None,
    page: int = 1,
    size: int = Query(25, le=100),
):
    must = (
        {"multi_match": {"query": q, "fields": ["message", "repo_name", "actor_login"]}}
        if q
        else {"match_all": {}}
    )

    filters: list[dict] = []
    if type:
        filters.append({"term": {"type": type}})
    if actor:
        filters.append({"term": {"actor_login": actor}})

    query = {"bool": {"must": must, "filter": filters}}

    resp = await es.search(
        index=settings.ES_INDEX,
        query=query,
        from_=(page - 1) * size,
        size=size,
        sort=["_score", {"created_at": "desc"}],
    )

    hits = resp["hits"]
    total = hits["total"]["value"] if isinstance(hits["total"], dict) else hits["total"]
    results = [_to_hit(h) for h in hits["hits"]]
    return SearchResponse(total=total, results=results)


@router.get("/stats", response_model=list[RepoStat])
async def stats():
    resp = await es.search(
        index=settings.ES_INDEX,
        size=0,
        aggs={"repos": {"terms": {"field": "repo_name.raw", "size": 10}}},
    )
    buckets = resp["aggregations"]["repos"]["buckets"]
    return [RepoStat(repo=b["key"], events=b["doc_count"]) for b in buckets]


@router.get("/event/{event_id}", response_model=EventHit)
async def get_event(event_id: str):
    try:
        doc = await es.get(index=settings.ES_INDEX, id=event_id)
    except NotFoundError:
        raise HTTPException(status_code=404, detail="Event not found")
    return _to_hit(doc)
Gotcha — v8 kwargs, not body= The elasticsearch-py v8 client takes query pieces as top-level keyword args (query=, from_=, size=, sort=, aggs=) — not the old body={...} dict. Passing body= is deprecated and mixing the two raises. And it's from_ with the underscore, every time.
Gotcha — the size cap returns 422, not a clamp size: int = Query(25, le=100) makes FastAPI reject ?size=500 with a 422 validation error (and documents the limit in /docs) rather than silently clamping. If you'd rather clamp, drop the le= and use min(size, 100) in the body instead — a deliberate design choice, not an accident.
Your Rep: add a ?repo= filter. Since repo_name is analyzed text, an exact term won't behave like the others — decide between a match on repo_name (fuzzy) and a term on repo_name.raw (exact). Implement one and be able to say why.
Solution — the repo filter code 
# in search(), add the param:
    repo: str | None = None,
# ...and inside the filters block:
    if repo:
        filters.append({"term": {"repo_name.raw": repo}})   # exact owner/repo
Why .raw A term query is not analyzed, so matching against the analyzed repo_name field would usually fail. The repo_name.raw keyword subfield (from P1's mapping) holds the whole owner/repo string un-tokenized — exactly what an exact filter needs. Want "contains" behavior instead? Use {"match": {"repo_name": repo}} in must.

6 · /stats & /event/<id>

Teach. Those two routes already live in the file you just wrote — let's read them on their own. /stats is a pure aggregation: size: 0 means "return no documents, just the buckets," and a terms agg on repo_name.raw gives the top repos by event count. /event/<id> is a direct document lookup that turns a missing doc into a clean 404.

@router.get("/stats", response_model=list[RepoStat])
async def stats():
    resp = await es.search(
        index=settings.ES_INDEX,
        size=0,
        aggs={"repos": {"terms": {"field": "repo_name.raw", "size": 10}}},
    )
    buckets = resp["aggregations"]["repos"]["buckets"]
    return [RepoStat(repo=b["key"], events=b["doc_count"]) for b in buckets]


@router.get("/event/{event_id}", response_model=EventHit)
async def get_event(event_id: str):
    try:
        doc = await es.get(index=settings.ES_INDEX, id=event_id)
    except NotFoundError:
        raise HTTPException(status_code=404, detail="Event not found")
    return _to_hit(doc)
Gotcha — catch NotFoundError, don't guess es.get() on a missing id raises elasticsearch.NotFoundError (whose v8 constructor needs meta=/body= if you ever construct one yourself). Catch it and re-raise as HTTPException(404) so the client gets a proper 404 instead of a 500.
Recall check
  1. What does size: 0 do in an aggregation query, and why do you want it here?
  2. Why aggregate on repo_name.raw instead of repo_name? (Same reason as P1.)
  3. What HTTP status should a lookup of a non-existent event return, and how do you make that happen?

8 · Test it without a real Elasticsearch

Teach. You don't want your unit tests to require a running ES cluster — that's slow and flaky. The trick: monkeypatch the async client's methods to return canned responses. Then you can assert both the response shape and the query your code built, in milliseconds, with no cluster.

search-api/tests/test_search.py 
import pytest
from elasticsearch import NotFoundError
from fastapi.testclient import TestClient

from app import es as es_module
from app.main import app

client = TestClient(app)


# ---- canned ES responses -------------------------------------------------

SEARCH_HITS = {
    "hits": {
        "total": {"value": 1},
        "hits": [
            {
                "_id": "42",
                "_score": 3.5,
                "_source": {
                    "type": "PushEvent",
                    "actor_login": "octocat",
                    "repo_name": "octocat/hello",
                    "message": "fix the bug",
                    "created_at": "2026-07-09T00:00:00Z",
                },
            }
        ],
    }
}

STATS_AGG = {
    "hits": {"total": {"value": 0}, "hits": []},
    "aggregations": {
        "repos": {
            "buckets": [
                {"key": "octocat/hello", "doc_count": 12},
                {"key": "torvalds/linux", "doc_count": 7},
            ]
        }
    },
}

EVENT_DOC = {
    "_id": "42",
    "_source": {
        "type": "PushEvent",
        "actor_login": "octocat",
        "repo_name": "octocat/hello",
        "message": "fix the bug",
        "created_at": "2026-07-09T00:00:00Z",
    },
}


@pytest.fixture
def stub_es(monkeypatch):
    """Monkeypatch the async ES client. Records last kwargs for assertions."""
    calls = {}

    async def fake_search(**kwargs):
        calls["search"] = kwargs
        if kwargs.get("size") == 0:  # /stats path
            return STATS_AGG
        return SEARCH_HITS

    async def fake_get(**kwargs):
        calls["get"] = kwargs
        if kwargs.get("id") == "missing":
            raise NotFoundError("not found", meta=None, body=None)
        return EVENT_DOC

    monkeypatch.setattr(es_module.es, "search", fake_search)
    monkeypatch.setattr(es_module.es, "get", fake_get)
    return calls


# ---- tests ---------------------------------------------------------------

def test_health():
    r = client.get("/health")
    assert r.status_code == 200
    assert r.json() == {"status": "ok"}


def test_search_maps_hits(stub_es):
    r = client.get("/search?q=fix")
    assert r.status_code == 200
    body = r.json()
    assert body["total"] == 1
    assert len(body["results"]) == 1
    hit = body["results"][0]
    assert hit["type"] == "PushEvent"
    assert hit["actor_login"] == "octocat"
    assert hit["repo_name"] == "octocat/hello"
    assert hit["message"] == "fix the bug"
    assert hit["score"] == 3.5
    # q present -> multi_match, not match_all
    query = stub_es["search"]["query"]
    assert "multi_match" in query["bool"]["must"]


def test_search_type_filter_in_query(stub_es):
    r = client.get("/search?type=PushEvent")
    assert r.status_code == 200
    query = stub_es["search"]["query"]
    # no q -> match_all
    assert "match_all" in query["bool"]["must"]
    # type -> term filter
    assert {"term": {"type": "PushEvent"}} in query["bool"]["filter"]
    # v8 kwargs present
    assert stub_es["search"]["from_"] == 0
    assert stub_es["search"]["sort"] == ["_score", {"created_at": "desc"}]


def test_search_size_capped(stub_es):
    r = client.get("/search?size=500")
    assert r.status_code == 422  # Query(le=100) rejects over-cap


def test_stats_maps_buckets(stub_es):
    r = client.get("/stats")
    assert r.status_code == 200
    body = r.json()
    assert body == [
        {"repo": "octocat/hello", "events": 12},
        {"repo": "torvalds/linux", "events": 7},
    ]
    assert stub_es["search"]["size"] == 0


def test_event_found(stub_es):
    r = client.get("/event/42")
    assert r.status_code == 200
    assert r.json()["repo_name"] == "octocat/hello"


def test_event_not_found(stub_es):
    r = client.get("/event/missing")
    assert r.status_code == 404
Build along: run the suite.
Solution — run the tests commands 
uv run pytest -q
# -> 7 passed
Gotcha — the stub must be async The real .search/.get are coroutines, so your fakes must be async def too (they return awaitables). A plain def returning a dict breaks the await. The fixture also records the kwargs your code passed, so a test can assert the term filter and from_/sort actually made it into the query — testing behavior, not just output.
Why FastAPI's TestClient is enough TestClient is synchronous and drives your async endpoints for you — no pytest-asyncio needed for this style. It spins the app in-process and issues real HTTP-shaped calls.

  2. Why must the fake methods be async def?

9 · Containerize the API

Teach. Same uv-based Dockerfile pattern as P1's Django image — copy the lockfile first for layer caching, then the code — but the command is uvicorn and the port is 8001. No --reload in the container.

search-api/Dockerfile 
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 \
    UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy
WORKDIR /app

# Deps first for layer caching
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project

COPY . .
ENV PATH="/app/.venv/bin:$PATH"

EXPOSE 8001
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8001"]
search-api/.dockerignore 
.venv/
__pycache__/
*.pyc
.git/
.pytest_cache/
Why no --reload --reload watches files and restarts on change — great for local dev, wasteful and slightly risky in a container image meant to run unattended. We'll still add the reload flag when running locally; the image ships the plain command.

11 · Runtime config & the server proxy

Teach. The browser should never call FastAPI directly — that means CORS headaches and leaking the API's address into client JS. Instead, the Nuxt Nitro server exposes /api/search and /api/stats routes that run on the server and forward to FastAPI. The browser only ever talks to Nuxt's own origin.

Step 1 — where the API URL lives

runtimeConfig holds the FastAPI base URL, overridable by an env var at run time (crucial for Compose/K8s, where it becomes http://search-api:8001).

frontend/nuxt.config.ts 
// https://nuxt.com/docs/api/configuration/nuxt-config
export default defineNuxtConfig({
  compatibilityDate: '2025-07-15',
  devtools: { enabled: true },

  // Global stylesheet
  css: ['~/assets/css/main.css'],

  runtimeConfig: {
    // Private (server-only). This is what the Nitro server routes use.
    apiBase: process.env.API_BASE || 'http://localhost:8001',
    public: {
      // Exposed to the client too, in case you ever call the API directly.
      apiBase: process.env.API_BASE || 'http://localhost:8001',
    },
  },
})

Step 2 — the proxy routes

Each Nitro handler reads the config, grabs the incoming query params, and $fetches the FastAPI backend. Return-type annotations keep it a typed proxy.

frontend/server/api/search.get.ts 
import type { SearchResponse } from '~/types/api'

// Server-side proxy: the browser calls /api/search, and this Nitro handler
// forwards the request to the FastAPI backend. Keeps the real API URL
// server-side and avoids browser CORS entirely.
export default defineEventHandler(async (event): Promise<SearchResponse> => {
  const config = useRuntimeConfig(event)

  // Pass through the query params the page sent (q, type, actor, page, size).
  const query = getQuery(event)

  return await $fetch<SearchResponse>('/search', {
    baseURL: config.apiBase,
    query,
  })
})
frontend/server/api/stats.get.ts 
import type { RepoStat } from '~/types/api'

// Server-side proxy for /stats -> FastAPI backend.
export default defineEventHandler(async (event): Promise<RepoStat[]> => {
  const config = useRuntimeConfig(event)

  return await $fetch<RepoStat[]>('/stats', {
    baseURL: config.apiBase,
  })
})
Why proxy at all Three wins: no CORS (same-origin from the browser's view), the FastAPI URL stays server-side (the private apiBase, not public), and you get one place to add caching/auth later. The pages call /api/search; they never know FastAPI's real address.
Gotcha — pass event to useRuntimeConfig In a Nitro handler you call useRuntimeConfig(event) (with the event), and read query params with getQuery(event). At runtime, the private apiBase is overridable by the NUXT_API_BASE env var — Nuxt maps NUXT_* onto runtimeConfig automatically. That's the hook Compose uses in step 15.

Pass 2 — filters, paging, and states

Teach. The finished page adds type/actor filters, a "search on click" pattern (form values copied into a submitted object so typing doesn't spam the API), an accumulating "Load more", and loading/empty/error states. Here it is in full:

frontend/pages/index.vue 
<script setup lang="ts">
import type { SearchResponse } from '~/types/api'

// --- form state (what the user types) ---
const q = ref('')
const type = ref('')
const actor = ref('')

// --- query state (what we actually send). We only copy the form values
// into these when the user clicks Search, so typing doesn't spam the API. ---
const submitted = reactive({
  q: '',
  type: '',
  actor: '',
})
const page = ref(1)
const size = ref(10)

// Accumulated results across "Load more" pages.
const results = ref<SearchResponse['results']>([])
const total = ref(0)

// useFetch re-runs automatically whenever a reactive value used in `query`
// changes. We type the response via the generic so `data` is fully typed.
const { pending, error, refresh } = await useFetch<SearchResponse>(
  '/api/search',
  {
    query: {
      q: () => submitted.q,
      type: () => submitted.type,
      actor: () => submitted.actor,
      page,
      size,
    },
    // Don't fire on first load until the user searches.
    immediate: false,
    default: () => ({ total: 0, results: [] }),
    // Runs after every fetch. Page 1 resets the list; later pages append.
    onResponse({ response }) {
      const body = response._data as SearchResponse
      total.value = body.total
      if (page.value === 1) {
        results.value = body.results
      } else {
        results.value = [...results.value, ...body.results]
      }
    },
  },
)

function onSearch() {
  submitted.q = q.value
  submitted.type = type.value
  submitted.actor = actor.value
  page.value = 1
  refresh()
}

const hasMore = computed(() => results.value.length < total.value)
const hasSearched = computed(
  () => submitted.q !== '' || submitted.type !== '' || submitted.actor !== '',
)

function loadMore() {
  page.value += 1
}

function truncate(text: string, max = 100): string {
  if (!text) return ''
  return text.length > max ? text.slice(0, max) + '…' : text
}

function formatDate(iso: string): string {
  const d = new Date(iso)
  return Number.isNaN(d.getTime()) ? iso : d.toLocaleString()
}
</script>

<template>
  <div>
    <h1>Search GitHub events</h1>

    <form class="filters" @submit.prevent="onSearch">
      <input
        v-model="q"
        class="grow"
        type="text"
        placeholder="Search text (q)"
      />
      <input v-model="type" type="text" placeholder="type (e.g. PushEvent)" />
      <input v-model="actor" type="text" placeholder="actor login" />
      <button type="submit" :disabled="pending">Search</button>
    </form>

    <p v-if="hasSearched" class="muted">{{ total }} result(s)</p>

    <p v-if="pending" class="center muted">Loading…</p>

    <p v-else-if="error" class="center muted">
      Something went wrong loading results.
    </p>

    <p v-else-if="hasSearched && results.length === 0" class="center muted">
      No events matched your search.
    </p>

    <div v-else>
      <article v-for="(r, i) in results" :key="i" class="card">
        <div class="row1">
          <span class="repo">{{ r.repo_name }}</span>
          <span class="badge">{{ r.type }}</span>
        </div>
        <p class="msg">{{ truncate(r.message) }}</p>
        <div class="meta">
          <span>@{{ r.actor_login }}</span>
          <span>{{ formatDate(r.created_at) }}</span>
          <span>score {{ r.score.toFixed(2) }}</span>
        </div>
      </article>

      <div v-if="hasMore" class="center">
        <button type="button" :disabled="pending" @click="loadMore">
          Load more
        </button>
      </div>
    </div>
  </div>
</template>
Why copy into submitted? If useFetch's query pointed straight at the input refs, every keystroke would fire a request. Instead the inputs bind to q/type/actor, and only onSearch() copies them into the reactive submitted object the query watches — so the API is hit on Search, and on Load more (which just bumps page).
Gotcha — typing useFetch Pass the response type as the generic (useFetch<SearchResponse>(…)) so data is typed, and always give a default so the template never dereferences null during loading or SSR.
Your Rep: the score is shown but you can't sort by recency. Add a "Newest / Relevant" toggle that appends a sort param the proxy forwards, and have FastAPI honor it (relevance is already _score; "newest" is created_at desc only). Small full-stack change touching the page, the proxy, and the endpoint — exactly the muscle this project builds.
Hint — where each change lands approach
  • page: a ref<'relevant'|'newest'> added to submitted and the fetch query.
  • proxy: nothing — getQuery(event) already forwards every param.
  • FastAPI: a sort: str = "relevant" param; when "newest", set sort=[{"created_at": "desc"}] instead of the _score-first list.
The lesson One user-facing feature, three layers, one shared contract. That's the day-to-day of full-stack work, and why the TS types mirroring the Pydantic models pays off — change the shape in one place, the compiler finds the other.

frontend/pages/stats.vue 
<script setup lang="ts">
import type { RepoStat } from '~/types/api'

// Simple fetch on page load. useFetch handles SSR + typing for us.
const { data, pending, error } = await useFetch<RepoStat[]>('/api/stats', {
  default: () => [],
})

// Biggest event count -> used to scale the bar widths (0..100%).
const maxEvents = computed(() => {
  const rows = data.value ?? []
  return rows.reduce((m, r) => Math.max(m, r.events), 0)
})

function widthPct(events: number): string {
  if (maxEvents.value === 0) return '0%'
  return `${Math.round((events / maxEvents.value) * 100)}%`
}
